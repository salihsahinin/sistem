# paralel-oturum-protokolu

**Üst blok:** Aynı anda açık birden çok Jarvis oturumu (terminal + masaüstü uygulaması + telefon) birbirinin işini bozmasın diye 4 kural. Salih imzası 2026-08-17 masa (KB-08 + KB-09 + KB-10 H4); kaynak vakalar: 08-12 (Docker motoru/kaynak çakışması), 08-15 (vaka-2, mükerrer koşum), 08-16 (vaka-3, 518k mükerrer workflow) · 08-21 (vaka-4, resume-körlüğü: numara çakışması + pointer kırılması). Durum: **kural** (deneysel damga m.29 — eşikler ilk 10 seansta kalibre). Uygulama: `seans-acilis` §1.4-1.5, `seans-kapanis` §7, KILAVUZ "Paralel seans protokolü".

**Çekirdek — 5 kural:**
1. **Canlı-oturum kapısı (açılış + her resume — Salih imzası 08-21, Karar 57):** son commit ≤15 dk ∧ kapsülde o seansın kapanış kaydı yok → "paralel-oturum şüphesi" beyanı; diğer oturumun manifestte **sahada** görünen işi ikinci kez koşulmaz, onun dosyalarına yazılmaz; hat paylaşımı Salih'e tek soru.
   *Resume eki (vaka-4, 08-21):* uzun oturumda özet-yenileme/dönüş sonrası ilk cevaptan önce kapı **yeniden** koşar (`git log -5` + kapsül başı) — vaka-4: resume-körlüğü seans-11↔12 karar-numarası çakışması (51-53 çift kullanım) + damıtma sonrası 14 kırık pointer üretti; onarım [ariza] f60d84e..bc4afd5.
2. **Koşum-önü manifest kapısı:** Workflow/atlas/pipeline açmadan önce `cc/pipeline-*.md` manifesti + `git log -15` okunur — iş zaten koşmuş/koşuyorsa devralınır, yeniden koşulmaz.
3. **Paylaşılan kaynak freni:** servis/konteyner/port/DB/soket açmadan önce mevcut durum okunur (`docker ps`, `lsof -i :PORT`); çakışma varsa **kurulmaz**, bildirilir; mevcut olan kullanılır. **Motor kapatma freni:** paylaşılan daemon (Docker vb.) yalnız diğer hatta iş kalmadığı doğrulanınca kapatılır.
4. **Commit freni (H4):** başka jarvis oturumu canlıyken `git add -A` **yasak**; her oturum kendi dosyalarını yol vererek commit'ler (`git add <yol>`); ekleme-esaslı yazım (yeniden oku → altına ekle) korunur.
5. **PR kuralı (Salih Katman-1, 2026-09-15, aynen: "bundan sonra her bir oturumumda create pr yapacağım. böylelikle conflictin önüne daha rahat geçebileceğiz tek bir fable oturumda merge yapılacak"):** her yan oturum (öğrenme şeritleri, Sonnet/Opus yan işleri, gnhf) kendi branch'inde çalışır (`claude/<seans>-<konu>`), işini commit'ler, `origin`'e push eder ve PR açar (gh-axi); **merge yalnız ana-sıra Fable oturumunda** (m.41 GK-2), çatışma çözümü orada. Push beyanı m.9: bu kural yan-oturum push'u için genel beyandır; main'e doğrudan commit yan oturumda yasak. H4 `git add <yol>` kuralı branch içinde de geçerli. **EK — worktree + origin/main tabanı (Salih Katman-1, 2026-09-15, aynen: "önerdiğin şekilde devam edelim"; gerekçe: 09-15 yan oturum ana checkout'ta çalıştı, PR #4 24 commit taşıdı, 17'si ana-sıranın push'lanmamış işi):** yan oturum Claude Code'da **worktree** seçeneğiyle açılır (ayrı çalışma ağacı; ana checkout'un yarım işine dokunamaz) ve ilk işi branch'ini `origin/main`'e oturtmaktır (`git fetch origin && git rebase origin/main`; PR yalnız kendi commit'lerini taşır, ana-sıra push'unu beklemez). Bilinen sınırlar: worktree'de `veri/baglam.sqlite` yoktur (gitignore) → SessionStart "silver bayat" der, öğrenme oturumu silver kullanmaz, koşmaz; untracked dosyalar (ör. `sonuc.json`) görünmez; yan oturum `seans-kapanis` koşmaz (kapsül/push ana-sıranın; PR açılınca işi biter, sekme kapatılır). **EK-2 — worktree beyanı (Salih Katman-1, 2026-09-18 seans açılışı, aynen: "bundan sonra friday dahil tüm oturumlar için worktree formatının açık olup olmaması gerektiğini sebebiyle belirt (oturum açmak için talimat verdiğinde). jarvis fable ana oturum worktree seçili olmadan açılıyor"):** Jarvis her oturum-açma talimatında tek satır yazar: `worktree: AÇIK | KAPALI — sebep`. Tablo: Jarvis Fable ana-sıra `~/jarvis` → **KAPALI** (kanon, kapsül, silver sqlite, merge ve push ana checkout'ta; worktree'de kapsül yazımı ana-sıraya düşmez) · `~/jarvis` yan oturum (öğrenme şeridi, Sonnet/Opus yan iş, gnhf) → **AÇIK** (ana checkout'un yarım işine dokunmaz; branch + PR; ilk iş rebase) · Friday `~/friday` → **KAPALI** (ayrı repo, tek oturum, kapsül kendi core'una yazar, PR hattı yok, dönüş dosyayla) · staj `~/staj başlangıç` → **KAPALI** (remote yok, tek oturum). Genel kural: worktree yalnız aynı checkout'u paylaşan ikinci oturum varsa açılır; Friday/staj'da ikinci oturum açılırsa **AÇIK**. **EK-3 — Friday emir teslimi otomatik (Salih onayı 2026-09-18 ~12:1x, aynen: "otomatize etme önerini onaylıyorum"):** Jarvis emri Friday reposuna commit'ledikten (`cc/gelen/gorev-*.md` + json + `.aktif-devir`) sonra masaüstü oturum-mesajı gönderir (`ccd_session_mgmt`: `list_sessions` ile `cwd == ~/friday` olan oturum seçilir — id her oturumda değişir, ada/id'ye sabitlenmez — sonra `send_message`): tek satır "cc/gelen/.aktif-devir → <emir yolu>, emirdir; sohbete bırakılmış say". Sürükleme emekli; Friday oturumu kapalıysa mesaj kuyruğa düşer, Salih oturumu açınca işlenir. İlk canlı kullanım: tur-6 (tur-5 09-18 elle bırakıldı). Yanlış-oturum freni: gönderim öncesi cwd + başlık brifte yazılır. **EK-4 — monorepo tablosu (Karar 101 F4, 2026-09-18; EK-2 tablosunu süpersede eder, EK-2 metni AS-OF kalır):** git kökü tek: `~/sistem`. Jarvis Fable ana-sıra cwd `~/sistem/jarvis` → worktree **KAPALI** (kanon, kapsül, silver sqlite, merge ve push ana checkout'ta) · Jarvis yan oturum (öğrenme şeridi, Sonnet/Opus yan iş, gnhf) cwd `~/sistem/jarvis` → worktree **AÇIK** (branch `claude/<seans>-<konu>` + PR; ilk iş `origin/main`'e rebase) · Friday cwd `~/sistem/friday` → worktree **KAPALI**, main, pathspec-only `git add <yol>`, push yok, PR hattı yok, dönüş `cc/giden/` dosyasıyla (Karar 99 M1 yeniden: Friday yan oturum değil, aynı depoda ayrı cwd'li ajan oturumu; commit'leri K1 kapısında `friday/` alanıyla görünür) · staj `~/staj başlangıç` → **KAPALI** (ayrı repo). Genel kural aynen: worktree yalnız aynı checkout'u paylaşan ikinci oturum varsa; Friday'de ikinci oturum açılırsa **AÇIK**. İki ajan aynı `main`'de: dizinler ayrık, çakışma yalnız aynı dosyada; H4 tek fren. **Karar 105 satırı (2026-09-21):** alan ajanları (`evals/` Turing · `guvenlik/` Kerckhoffs · `baglam/` Shannon · `hesaplama/` Knuth) cwd `~/sistem/<alan>` → worktree **KAPALI**, main, pathspec-only, push yalnız Salih beyanıyla, PR yok; öğrenme oturumu artık jarvis worktree'si değil alan ajanı oturumudur ("seans başı, <şerit>" o dizinde), ders iskeleti Jarvis'ten `cc/gelen/`. Eski "Jarvis yan oturum (öğrenme şeridi) worktree AÇIK" satırı öğrenme için `gecerli-bitis: 2026-09-21` (Sonnet/Opus yan iş ve gnhf için bakî).

**Neden:** paralel seans Jarvis'in kendi kararı (m.36 rev.); tek çalışma ağacı + iki oturum = birinin yarım işini diğerinin yayımlaması, mükerrer koşum (08-15/16 toplam ~549k token), sessiz kaynak bozulması. Senkron elle yürür (K-009 otomasyonu açılınca otomatikleşmesi beklenir).

**Gotchas:** yanlış-pozitif (sen kapatmışsın ama commit taze) → tek soru yeter, iş durmaz · staj oturumu ayrı klasör/ayrı ritüel (md.49) ama paylaşılan makine kaynakları (Docker/port) bu kurala **tabi** · telefon oturumu yan-oturumdur, kanon yazmaz (m.41) · **araç-kaynaklı dal değişimi (vaka 08-21 s13):** diğer oturumun [[no-mistakes]] koşumu working tree'yi dala geçirip merge yürütebilir (UU çakışma + staged dosyalar) — bu hâldeyken commit atmak merge'i yabancı adına tamamlar ya da yanlış dala yazar; git-yazma işlemleri ağaç main'e dönüp temizlenene dek **bekletilir**, sonra pathspec'li commit (`git commit -- <yol>`) diğer oturumun stage'ini dışarıda tutar · manifest-kapısı grep'i varyant-toleranslı yazılır (tire/boşluk: `ATLAS[- ]?V59` vakası 08-21 — tireli desen boşluklu başlığı ıskaladı, kısmi mükerrer koşum; **kural-adayı** Salih'te).
