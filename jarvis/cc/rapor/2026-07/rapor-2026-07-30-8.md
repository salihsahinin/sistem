## §2 — DOCKER NEDİR: doğru zihinsel model

### 2.1 — Konteyner ↔ sanal makine: tek cümlelik fark ve neden önemli

**Sanal makine (VM):** kendi çekirdeğini (kernel) çalıştıran, sanallaştırılmış donanım üstünde duran tam bir işletim sistemi. Ayrım donanım seviyesindedir.
**Konteyner:** ana makinenin çekirdeğini **paylaşan**, yalnız kullanıcı-uzayı yalıtılmış bir süreç grubu. Ayrım çekirdek özellikleriyle (namespace, cgroup, capability) kurulur.

Neden önemli: konteynerde bir çekirdek açığı bulunursa ayrım kalkar. Docker'ın kendi belgesi bunu birebir kabul ediyor: *"the default set of capabilities and mounts given to a container may provide incomplete isolation, either independently, **or when used in combination with kernel vulnerabilities**"* `[D]`.

**Üç nesne, karışması en sık üç kavram:**
- **İmaj (image):** dondurulmuş, salt-okur şablon — "kurulu bir sistemin fotoğrafı". Örnek: Python 3.12 + yfinance + pandas kurulu bir Linux.
- **Konteyner:** o imajdan doğmuş **çalışan örnek**. Ölünce yazdıkları kaybolur.
- **Birim (volume) ∧ bağlama (bind mount):** konteyner ölünce kaybolmasın diye dışarı açılan kapı. **Bizim bütün tartışmamız bu üçüncü nesnenin etrafındadır** (H2).

Somut örnek, bizim vakamızla: *imaj* = "Claude Code + git kurulu Ubuntu" · *konteyner* = o imajdan açılmış bir denetçi koşumu · *bağlama* = `C:\JARVIS\kuyruk` klasörünü konteynerin içine `:ro` (salt-okur) vermek. Üçüncüsünü yanlış kurarsan ilk ikisi hiçbir şey korumaz.

### 2.2 — Windows'ta ne oluyor

Docker Desktop, Windows üstünde Linux konteynerlerini **WSL2** arka ucuyla koşar: WSL2 aslında hafif bir Hyper-V sanal makinesidir; Linux konteynerleri o VM'in içinde yaşar. Yani Windows'ta "konteyner" fiilen **VM içindeki konteynerdir** — bir katman fazladan ayrım var, ama bir katman fazladan kaynak da var.

**Docker Desktop sistem gereksinimleri (birincil):** `[D]`
| Kalem | Gereksinim | Bizim makine `[X]` |
|---|---|---|
| Windows | *"Windows 11 64-bit: Enterprise, Pro, or Education version 23H2 (build 22631) or higher"* | **Windows 11 Pro, build 26200** ✓ |
| WSL | *"WSL version 2.1.5 or later"* | **WSL YÜKLÜ DEĞİL** ✗ (kurulacak) |

**Kaynak tüketimi — dürüst tablo.** Burada ölçülmüş kendi rakamımız YOK; iki tür rakam var:

- **Üst sınır (belgeden, `[D]`):** WSL2 VM'inin varsayılan bellek tavanı *"50% of total memory on Windows"*; varsayılan takas alanı *"25% of memory size on Windows rounded up to the nearest GB"*. ⇒ **Bizim makinede tavan ≈ 7,9 GB RAM + ≈ 4 GB disk-takas** `[X]` (15,75'in yarısı / çeyreği). Bu bir **tavan**, tahsis değil: varsayılan `autoMemoryReclaim = dropCache` önbelleği hemen geri veriyor `[D]`, `vmIdleTimeout` varsayılanı 60.000 ms `[D]`.
- **Saha rakamı (`[K]`, çelişkili):** "boşta 3 GB yiyor" ↔ "`autoMemoryReclaim=gradual` ile boşta **209 MB**'a indi". İki rakam arası **14 kat** — bu ayrım konfigürasyona bağlı, tek sayı olarak alıntılanamaz.

**Kritik bağlam `[X]`:** ölçüm anında makinede **boşta yalnız 3,07 GB RAM** vardı (toplam 15,75). En büyük tüketiciler: Memory Compression 647 MB · chrome 599 MB · claude 515+507+440 MB (üç oturum) · msedgewebview2 505 MB. ⇒ **Docker Desktop'ın varsayılan WSL2 tavanı (7,9 GB), bugünkü boş RAM'in (3,07 GB) 2,6 katıdır.** Bu, "kurulur ama `.wslconfig` ile bellek sınırı ELLE konur" demektir — kurulumun opsiyonel değil **zorunlu** bir adımı. Kurup ayarlamamak, Salih'in paralel oturum alışkanlığıyla (aynı anda 3 claude + chrome) doğrudan çarpışır.

**Disk `[K]`:** kurulum için ~6 GB; kurucu ~640 MB; gerçek kullanımda imaj/katman birikimiyle 20-40 GB'a çıkabildiği bildiriliyor. Bizde 229 GB boş ⇒ **disk kısıt değil.**

### 2.3 — Lisans (birincil kaynak)

Docker'ın kendi belgesi `[D]`: Docker Desktop **ücretsizdir** şu hallerde — *"Small businesses (fewer than 250 employees **AND** less than $10 million in annual revenue)"* · *"Personal use"* · *"Education"* · *"Non-commercial open source projects"*. Ücretli abonelik (Pro/Team/Business) gerekir: *"Professional use in larger organizations"* · *"Government entities"*. Ayrıca birebir: *"The licensing and distribution terms for Docker and Moby open-source projects, **such as Docker Engine, aren't changing**"* `[D]`.

**Bizim vakamıza uygulama `[X]`:** Salih birey; JARVIS bir **şirket simülasyonudur**, tüzel kişilik değil; kullanım kişisel + eğitim amaçlı. ⇒ **Ücretsiz katman kapsar, tereddüt yok.** Tek dikkat: eşik **şirkete** bakar, geliştiriciye değil — staj bağlamında (Otonet/Otoplus) Docker Desktop'ı **işveren işi için** kullanmak, işverenin eşiği aşıp aşmadığına bağlıdır; bu bizim değil işverenin sorunudur ama bilinmesi gerekir `[X]`.

**Ücretsiz alternatifler `[K]`:** Podman Desktop (Apache 2.0) ∧ Rancher Desktop (Apache 2.0) — *"no employee-count thresholds, no 'free for personal use' caveats"*; ikisi de eşiksiz ücretsiz. WSL2 üstünde **saf Docker Engine** (Desktop'sız) — Apache 2.0, lisans sorusu hiç doğmaz `[D]`, ama GUI/otomatik güncelleme yok, kurulum el işi.
**Bizim kullanımımızı karşılar mı `[X]`:** Evet, üçü de — **çünkü bizim ihtiyacımız GUI değil, bağlama kümesi kontrolüdür.** Lisans bu kararda **bağlayıcı bir eksen değildir** (ücretsiz katman zaten bizi kapsıyor); alternatifler ancak Docker Desktop'ın kaynak yükü sorun olursa devreye girer. ⇒ Bu eksene bu raporda ağırlık verilmedi, bilinçli.

## §4 — ENTEGRASYON SENARYOLARI

### S1 · Ajan hapsi — kilit sorununun yapısal cevabı

**Ne çözer.** 30-6'nın ölçtüğü koşullu kilidi, ayar-yükleme katmanından **varlık katmanına** taşır (H3).

**Nasıl kurulur (somut, bizim yığınımızda) `[X]`:**
1. `winget install -h Docker.sbx` → `sbx login` (Docker hesabı, tarayıcı OAuth `[D]`).
2. Ön koşul: Windows Hypervisor Platform özelliği açık olmalı `[D]` — bizde durum **doğrulanamadı** (sorgu yönetici hakkı istedi; `HypervisorPresent=True` olumlu işaret ama aynı şey değil, §9/3).
3. `sbx create --clone claude .` `[K]` — ajan mikro-VM içindeki **özel git klonunda** çalışır; ana makinede `sandbox-<ad>` uzak deposu belirir.
4. Ürün alma: `git fetch sandbox-<ad>` → `git diff main..sandbox-<ad>/main` → beğenirsen birleştir `[K]`.
