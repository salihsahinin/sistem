## 3. Kendini-Geliştiren Hafıza Mekanizmaları ve Frenler

- **Claude Code auto memory** (K1): Fren = boyut sınırı (200 satır/25KB) + insan her zaman `/memory` ile okuyup silebilir/düzenleyebilir; otomatik yazma insan onayı **beklemez**, ama tamamen şeffaf (plain markdown, diff görülebilir) ve geri alınabilir (silme yasağı yok, dosya düzeyinde elle müdahale var).
- **Claude memory tool (API)** (K2): Fren geliştiriciye devredilmiş — "hassas bilgi yazma" konusunda model genelde reddeder ama garanti değil, ek doğrulama önerilir; süre-bazlı silme de geliştiricinin sorumluluğu, araç kendiliğinden fren koymaz.
- **Context editing/compaction** (K3, K4): Fren = eşik-tabanlı otomatik tetik (token limiti), insan onayı yok; "effective context engineering" yazısı (K3) genel ilke olarak "en küçük yüksek-sinyal token seti" hedefini koyar, aşırı-toplama karşıtı bir tasarım ilkesi.
- **OpenAI Agents SDK compaction** (K5): Fren = eşik kontrolü (candidate meets threshold), otomatik ve insan müdahalesi yok; yan etki dokümante edilmiş ("can block streaming" — bilinen kısıt, gizlenmemiş).
- **Letta/MemGPT self-editing** (K10): En zayıf fren gözlemi — dokümanda **insan onayı veya denetim katmanından hiç bahsedilmiyor**; hem agent'ın kendisi hem "sleep-time agent" adlı ayrı bir uzman ajan aynı bellek bloklarını serbestçe değiştirebiliyor. Bu, incelenen ürünler arasında en gevşek fren yapısı.
- **Mem0 consolidation** (K13/K14, doğrulanmamış): ADD/UPDATE/DELETE/NOOP kararı LLM tarafından otomatik veriliyor; insan onay adımı snippet'lerde belirtilmedi (kaynak açılamadığı için kesin hüküm verilemez).
- **LangMem background manager** (K15, K16): Zamanlanmış (cron) tetik, insan onayı yok; "memory hoarding" karşıtı konsolidasyon tasarım hedefi olarak belirtiliyor ama uygulama detayı (ör. çelişki çözüm kuralı) bu koşumda görülen sayfalarda yok.
- **Genel örüntü:** İncelenen 7 üründen **hiçbirinde** yazma/güncelleme adımında zorunlu insan onayı bulunmuyor; frenler ya boyut/bütçe eşiği (Claude Code, context editing) ya da geliştiriciye devredilmiş sorumluluk (memory tool, ADK, Mem0) biçiminde. Letta en açık şekilde onaysız çalışıyor.

## 4. Çok-Ajan İzolasyon / Paylaşım

- **Claude Code** (K1): Alt-ajanlara ana konuşmanın auto memory'si **yüklenmez** (fork istisna); alt-ajanın kendi auto memory'si ayrı bir dizindir — en net dokümante edilmiş izolasyon kuralı bu koşumda.
- **Claude memory tool** (K2): İzolasyon tamamen uygulama tasarımına bırakılmış (`/memories` altında kullanıcı/oturum bazlı dizin eşleme geliştiriciye ait); araç kendisi ajan-başına ayrım dayatmaz.
- **Anthropic multi-agent araştırması** (K4 arama özetinde geçti, doğrudan açılmadı bu koşumda): "çok sayıda izole bağlamlı ajan tek-ajan sistemlerden üstün" bulgusu — iddia, K4 WebSearch özetinden, tam metin bu koşumda doğrulanmadı.
- **Google ADK** (K9): SessionService (oturum-içi) ve MemoryService (uzun-vadeli) ayrı arayüzler; ajanlar arası paylaşım/izolasyon kuralı dokümanda **belirtilmemiş** — backend seçimine bırakılmış boşluk.
- **Letta/MemGPT** (K10): "sleep-time agent" gibi uzman ajanlar aynı hafıza bloklarını değiştirebiliyor — bu **paylaşılan yazma erişimi**, izolasyon değil.
- **OpenAI Agents SDK** (K5) ve **LangMem** (K15): Session/namespace nesnesi bazlı ayrım mümkün ama zorunlu bir izolasyon kuralı dokümanlarda görülmedi; tasarım kararı geliştiriciye ait.
- **Mem0** (K13/K14): Kullanıcı-bazlı izolasyon iması var ("per user" ölçüm rakamı) ama çok-ajan senaryosu için ayrı kural doğrulanamadı (kaynak açılamadı).

## 5. İDDİA LİSTESİ (numaralı, gerekçesiz, ≤12)

1. Claude Code'da CLAUDE.md insan-yazımlı, auto memory ise dört tipe (`user`/`feedback`/`project`/`reference`) ayrılmış Claude-yazımlı notlardır (K1).
2. Claude Code auto memory `MEMORY.md` dosyası 200 satır veya 25KB sınırına tabidir, aşımda Claude'a otomatik kısaltma uyarısı döner (K1).
3. Claude Code'da alt-ajanlara ana konuşmanın auto memory'si yüklenmez; fork bu kuralın istisnasıdır (K1).
4. Claude memory tool `/memories` dizininde istemci-taraflı çalışır, Claude 4 ve sonrası modellerde kullanılabilir (K2).
5. Claude'un memory tool + context editing kombinasyonu Anthropic'in iç ajan-arama değerlendirmesinde %39 iyileşme sağlamıştır (K4).
6. Anthropic context editing yalnız istemci tarafında eski tool-result'ları temizler; compaction ise sunucu tarafında tüm konuşmayı özetler (K2).
7. OpenAI Agents SDK'da `OpenAIResponsesCompactionSession` eşik-tabanlı otomatik sıkıştırma yapar ve bu akışı bloke edebilir (K5).
8. ChatGPT'de "saved memories" kullanıcı talimatıyla, "chat history reference" ise geçmiş sohbetlerden örtük RAG-tabanlı erişimle çalışır (K8, ikincil kaynak, K6/K7 doğrudan açılamadı).
9. Google ADK'da Session (kısa-vadeli state) ile MemoryService (uzun-vadeli, aranabilir) ayrı arayüzlerdir; unutma/silme politikası dokümanda belirtilmemiştir (K9).
10. Letta/MemGPT üç katmanlı bellek kullanır: core (bağlam-içi), recall (aranabilir geçmiş), archival (vektör DB); ajan kendi belleğini fonksiyon çağrısıyla düzenler ve dokümanda insan onay katmanı yoktur (K10).
11. Mem0 dört aşamalı bir pipeline kullanır (extraction → consolidation → storage → retrieval) ve consolidation adımında LLM ADD/UPDATE/DELETE/NOOP kararı verir (K13/K14, kaynak doğrudan açılamadı, ikincil doğrulama).
12. LangChain/LangMem hafızayı semantik/epizodik/prosedürel olarak ayırır ve hot-path (canlı, agent yazımlı) ile background (zamanlanmış, ayrı yönetici süreç) olmak üzere iki yazma yolu tanımlar (K15).
