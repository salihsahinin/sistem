## AİLE A — GÖREV-AS-FONKSİYON

*Tez: görev, tipli girdi/çıktı alanları · ön/son-koşul · true/false dalları olan bir FONKSİYON gibi tanımlanmalı.*

### A.1 Programatik prompt/görev çerçeveleri — sözleşme alan setleri

**DSPy Signature** [D — https://dspy.ai/getting-started/expanding-signatures/ · https://dspy.ai/getting-started/program-dont-prompt/]
- Sözdizimi: string-signature `"girdi1, girdi2 -> çıktı1, çıktı2"`; tip belirtimi `alan: tip` ile — görülen örnek `"location, mood, contains_pun: bool -> haiku"`. Tip **zorlaması (coercion) ve doğrulama** sağlıyor.
- **Alan-adı = talimat ilkesi** (dokümandan birebir): *"A field called `research_request` will produce better completions than one called `request`, with no other changes."* Yani sözleşmedeki alan İSMİ, başka hiçbir şey değişmeden çıktı kalitesini değiştiriyor.
- Katmanlama: Signature (sözleşme) → Module (Predict = temel · ChainOfThought = akıl-yürütme katmanı · ReAct = araç-entegre ajan). Karmaşık görevde class-based signature önerilir, docstring = talimat.
- Bu iki sayfada ölçülmüş kazanç rakamı YOK (rakamlar A.3 Assertions ve C-ailesi MIPROv2 tarafında).

**LMQL** [D — https://lmql.ai/docs/]
- Kısıt dili: `where`-cümlesi. Dokümandan birebir örnek: `"Say 'this is a test':[RESPONSE]" where len(TOKENS(RESPONSE)) < 25`.
- Karakter-seviyesi kısıtlar otomatik olarak (sub)token maskelerine çevriliyor ("eager" değerlendirme) — yani sözleşme decoding katmanında ZORLANIYOR, sonradan doğrulanmıyor.
- Tipli değişken tanımı bu sayfada gösterilmedi; ölçülmüş kazanç rakamı YOK **[X — sayfa düzeyinde negatif bulgu]**.

**Guidance** [D — https://github.com/guidance-ai/guidance]
- Primitifler: `gen(max_tokens=20)` · regex-kısıtlı `gen("lm_age", regex=r"\d+")` · `select(["A","B","C","D"], name="model_selection")` — **kapalı seçenek kümesine kısıtlama** (jarvis'in "kapalı tip" ingest kararının doğrudan akrabası).
- Üç kısıt kademesi: regex → context-free grammar → JSON Schema (Pydantic ile tip güvenliği; örnek `systolic: int = Field(gt=300, le=400)` — yani **alan-başına aralık kısıtı** = invariant).
- "Token fast-forwarding" anılıyor ama sayısal iyileştirme verilmemiş **[X]**.

**SGLang** [D kısmi — https://docs.sglang.ai/]
- Ana sayfa kurulum/genel-bakış ağırlıklı; gen/select frontend primitifleri ve RadixAttention'ın teknik tanımı derin sayfalara inilemediği için alınamadı. Yalnız ölçek iddiası ("trillions of tokens/day across 400,000+ GPUs"). Karşılaştırmalı throughput rakamları **[X — doğrulanamadı]**.

**Sentez A.1:** Dört çerçevede de ortak çekirdek şu üçlü: **(i) adlandırılmış+tipli alanlar · (ii) alan-başına kısıt (regex/aralık/kapalı-küme) · (iii) doğal-dil talimatın yapısal bir SLOT'a (docstring/description) yerleşmesi.** "Alan adı = talimat" bulgusu, jarvis'in görev-emri şablonu için doğrudan operasyoneldir: başlık isimleri kozmetik değil.

### A.3 Design-by-Contract'ın ajanlara uygulanması

**DSPy Assertions** [D — arxiv.org/abs/2312.13382]
- Tanım: LM Assertions = "LM'lerin karşılaması gereken hesaplamalı kısıtlamalar" — postcondition sözleşmesinin doğrudan karşılığı.
- Ölçülmüş kazanç (abstract, birebir): *"passing constraints up to **164% more often** and generating up to **37% more** higher-quality responses"* (dört metin-üretim vaka çalışması).
- Suggestion↔Assertion ayrımı ve backtracking mekaniğinin detayı abstract düzeyinde yok **[X]**.

**AgentSpec** [D — arxiv.org/abs/2503.18666] — *bu ailenin en güçlü sözleşme bulgusu*
- Tanım (birebir): *"a lightweight domain-specific language for specifying and enforcing runtime constraints on LLM agents... structured rules that incorporate **triggers, predicates, and enforcement mechanisms**"*.
- Üçlü yapı DbC'ye 1:1 oturuyor: **trigger ≈ precondition · predicate ≈ invariant · enforcement ≈ postcondition/yaptırım**.
- Ölçülmüş: kod-ajanında **güvensiz yürütmelerin >%90'ı önlendi** · embodied ajanda tehlikeli eylemler **%100** elimine · otonom araçta **%100 uyum** · ek yük **milisaniye** düzeyinde.
- LLM'e kural yazdırma (o1 ile otomatik kural üretimi): **precision %95,56 / recall %70,96**; riskli kodun **%87,26'sı** yakalandı.

## AİLE B — HAFIZA-AS-IMPORT (bağlam montajı)

*Tez: ajana her şey verilmez; görev-hedefine göre derlenen bir bağlam-manifesti verilir (`import X from Y`).*

### B.1 Hedefe göre bağlam derleme — JIT / progressive disclosure

**Anthropic, "Effective context engineering for AI agents"** [D — anthropic.com/engineering/effective-context-engineering-for-ai-agents · **not: `-for-agents` sonlu URL 404 veriyor, doğru adres `-for-ai-agents`**]
- JIT tanımı (birebir): *"Rather than pre-processing all relevant data up front, agents built with the 'just in time' approach maintain **lightweight identifiers** (file paths, stored queries, web links, etc.) and use these references to dynamically load data into context at runtime using tools."* — **jarvis'in m.20 pointer sisteminin birebir sektör karşılığı.**
- Dosya-sistemi sinyalleri örtük bağlam taşır: *"the presence of a file named `test_utils.py` in a `tests` folder implies a different purpose than..."*; *"Agents can assemble understanding layer by layer, maintaining only what's necessary in working memory."*
- Compaction tanımı: bağlam sınırına yaklaşan konuşmayı özetleyip yeni pencereyle yeniden başlatma; **mimari kararlar + çözülmemiş buglar korunur, gereksiz araç-çıktıları atılır.**
- Bu makalede **ölçülmüş token/başarı rakamı YOK** — yalnız nitel ilke [D, negatif bulgu].

**Anthropic, "Code execution with MCP"** [D — anthropic.com/engineering/code-execution-with-mcp]
- **Rakam doğrulandı (birebir):** *"This reduces the token usage from **150,000 tokens to 2,000 tokens**—a time and cost saving of **98.7%**."* (senaryo: Google Drive'dan belge çekip Salesforce'a ekleme.)
- Mekanizma: *"Presenting tools as code on a filesystem allows models to read tool definitions **on-demand**, rather than reading them all up-front."* Ajan `./servers/` dizinini listeler, yalnız ihtiyaç duyduğu `getDocument.ts`'i okur. **Dizin = paket · dosya = modül · okuma = import.** Tezin en birebir sektör karşılığı budur.

**Anthropic, Agent Skills** [D] — üç kademeli açılım net tanımlı:
1. **Seviye 1 (metadata):** *"At startup, the agent pre-loads the `name` and `description` of every installed skill into its system prompt."* — her zaman yüklü (eager).
2. **Seviye 2 (gövde):** *"If Claude thinks the skill is relevant to the current task, it will load the skill by reading its full `SKILL.md` into context."* — model kendi karar verir.
3. **Seviye 3+ (ek dosyalar):** *"...which Claude can choose to navigate and discover only as needed."* Sonuç: *"the amount of context that can be bundled into a skill is effectively **unbounded**."*
- Somut token boyutu verilmemiş [X].

**Anthropic, "Writing effective tools for agents"** [D] — pagination/filtering/truncation + makul varsayılanlar; Slack örneğinde "concise" yanıt modu ~**⅓ token** kullanıyor. Başarı grafikleri görsel-only, metinden sayı çıkarılamadı [X].

### B.2 "Import" semantiği taşıyan gerçek örnekler — VE TEZE BİR DÜZELTME

**⚠️ Bu ailenin en önemli bulgusu — analojinin nerede TUTTUĞU, nerede KIRILDIĞI:**

**Claude Code CLAUDE.md `@import`** [D — code.claude.com/docs/en/memory]
- *"Imported files are expanded and loaded into context **at launch** alongside the CLAUDE.md that references them."* Özyinelemeli, **max 4 hop derinlik**.
- Kritik cümle (birebir): *"Splitting into imports helps organization but **doesn't reduce context**, since imported files load at launch."*
- **Sonuç: CLAUDE.md `@import` LAZY DEĞİL, EAGER'dır** — C'deki `#include` / static linking gibidir, Python `import`u gibi değil. Salih'in "program başındaki import satırları" analojisi biçim olarak doğru ama **maliyet davranışı bakımından yanıltıcı**: `@import` bağlam maliyetini AZALTMAZ, yalnız düzenler.

Gerçek lazy/JIT olan üç mekanizma (aynı belge, [D]):
1. **Alt-dizin CLAUDE.md'leri:** *"Instead of loading them at launch, they are included when Claude reads files in those subdirectories."*
2. **`.claude/rules/` path-scoped (frontmatter `paths:`):** *"Path-scoped rules trigger when Claude reads files matching the pattern, not on every tool use."* — glob-tetiklemeli gerçek JIT.
3. **Auto-memory topic dosyaları:** *"Topic files like `debugging.md`... are not loaded at startup. Claude reads them on demand."* Yalnız `MEMORY.md`'nin ilk **200 satır / 25KB**'ı her zaman yüklü — bu bir **index/manifest katmanı** (`__init__.py` benzeri).

**Cursor `.cursor/rules`** [D — cursor.com/docs/context/rules] — dört tetikleme tipi:

| Tip | Tetikleyici |
|---|---|
| Always Apply | `alwaysApply: true` → her oturumda (eager) |
| **Apply Intelligently** | model `description` alanını okuyup alaka kararı verir — *"Agent reads the description and pulls the rule in when relevant."* |
| Apply to Specific Files | `globs` eşleşince |
| Apply Manually | `@kural-adı` ile elle çağırma |

"Apply Intelligently" = Agent Skills Seviye-2 ile aynı desen. GitHub'dan uzak kurallar `.cursor/rules/imported/<repoName>/` altına senkronize ediliyor — **literal "imported" dizin adı kullanılıyor**.

**AGENTS.md** [D — agents.md] — *"Think of AGENTS.md as a README for agents."* Monorepo davranışı: OpenAI ana deposunda **88 AGENTS.md dosyası**; *"Agents automatically read the nearest file in the directory tree, so the closest one takes precedence."* Kendi import mekanizması yok [X], ama Claude Code onu `@AGENTS.md` ile içeri alıyor.

**MCP Resources ↔ Tools ayrımı** [D — modelcontextprotocol.io spec, 2026-07-28]
- **Resources = "application-driven"**: *"host applications determin[e] how to incorporate context based on their needs"* — URI ile adreslenen, `priority`/`audience` annotasyonlu, **uygulama tarafından seçilip yüklenen içerik**. MCP'de "import listesi/manifesti"ne en yakın kavram budur.
- **Tools = "model-controlled"**: model bağlamsal anlayışına göre keşfeder ve çağırır — fonksiyon-çağrısı/RPC semantiği, import değil.
- **Tez için sonuç:** protokol düzeyinde "veriyi içeri al" (import) ile "yetenek çağır" (call) ayrımı zaten kodlanmış. Jarvis'in şablonu bu iki yakayı KARIŞTIRMAMALI.
- **Ek bulgu [D]:** MCP artık `tools/list` ve `resources/list` yanıtlarına `ttlMs` ve `cacheScope` (`public`/`private`) alanları koyuyor — yani **protokol seviyesinde bir "manifest cache" kavramı** zaten var. Jarvis'in manifest şemasına doğrudan taşınabilir iki alan: *bu bağlam kaleminin tazelik süresi* + *paylaşım kapsamı*.

### B.3 Rol-başına bağlam farkı — ve ana gerilim

**Anthropic multi-agent research system** [D]
- İzolasyon gerekçesi: *"Subagents facilitate compression by operating in parallel with their own context windows."* + *"Each subagent also provides **separation of concerns**—distinct tools, prompts, and exploration trajectories—which reduces **path dependency**."*
- Alt-ajana verilen minimal, yapılandırılmış paket: *"Each subagent needs an **objective**, an **output format**, **guidance on the tools and sources** to use, and clear **task boundaries**."* — ham konuşma geçmişi DEĞİL.
- Geri dönüş de sıkıştırılmış: *"Subagents call tools to store their work in external systems, then pass **lightweight references** back to the coordinator."* (Literal "need-to-know" ifadesi geçmiyor [X], ama pratik aynı.)

**Cognition, "Don't Build Multi-Agents"** [D — cognition.com/blog/dont-build-multi-agents; `.ai` adresi 301 ile buraya yönlendiriyor] — **doğrudan karşı-görüş:**
- *"Actions carry implicit decisions, and conflicting decisions carry bad results."*
- *"The decision-making ends up being too dispersed and context isn't able to be shared thoroughly enough between the agents."*
- Somut arıza: Flappy Bird klonu — bir alt-ajan arka planı Super Mario tarzında, diğeri kuşu başka stilde üretiyor. *"Subagent 1 and subagent 2 cannot see what the other was doing"* · *"...based on conflicting assumptions not prescribed upfront."*
- Önerilen alternatif: tek-threadli doğrusal ajan + geçmişi özetleyen ayrı bir sıkıştırma-LLM'i.

**⚠️ GERİLİMİN ÇÖZÜMÜ (sentez — K, bu raporun kendi hükmü, birebir alıntı değil ama iki kaynağın kendi örnekleriyle tutarlı):** Anthropic ve Cognition **aynı olguyu** (izole bağlam) farklı görev sınıfları için yorumluyor. **Bağımsız BİLGİ-TOPLAMA paralelleşir** (örtüşmeyen keşif, path-dependency azalır) · **birbirine bağımlı ÜRETİM/TASARIM paralelleşmez** (örtük kararlar paylaşılmadan tutarlılık kırılır). Jarvis için operasyonel kural: alt-ajan dağıtmadan önce sorulacak tek soru — *"bu alt-görevler bağımsız bilgi mi topluyor, yoksa ORTAK bir çıktıyı mı üretiyor?"*

**LangChain, "Context Engineering for Agents"** [D — langchain.com/blog/context-engineering-for-agents] — dört-strateji taksonomisi: **Write** (pencere dışına kaydet: scratchpad/memory) · **Select** (*"pulling it into the context window"* = JIT) · **Compress** (*"retaining only the tokens required to perform a task"*) · **Isolate** (*"splitting it up"* = multi-agent/sandbox). Rakam: RAG üzerinden araç-getirimi *"improve[s] tool selection accuracy by **3-fold**"*. Claude Code auto-compact eşiği ~**%95 doluluk** [K — ikincil aktarım].

### B.4 Manifest formatı + prompt-cache uyumu — "import'lar en başta" kuralının sert gerekçesi

**Anthropic prompt caching** [D — claude.com/blog/prompt-caching (duyuru) + platform.claude.com/docs/en/build-with-claude/prompt-caching (docs.claude.com buraya 302)]
- **Rakamlar doğrulandı (duyuru, birebir):** *"reducing costs by up to **90%** and latency by up to **85%** for long prompts."*
- Cache-read fiyatı **0,1× base input**. Minimum cache-edilebilir uzunluk: **1.024 token** (Sonnet ailesi); bazı modellerde 2.048/4.096.
- **Maksimum 4 cache breakpoint**; lookback penceresi **20 blok** (*"The system checks at most 20 positions per breakpoint"*). TTL: varsayılan **5 dakika** (ephemeral), opsiyonel **1 saat** (yazma 2×, okuma yine 0,1×).
- **En kritik kural (dokümandan birebir):** *"**Key takeaway:** Place `cache_control` on the last block whose prefix is identical across the requests you want to share a cache."* Karşı-örnek de belgede: statik sistem bağlamı (blok 1-5) + her istekte değişen timestamp/kullanıcı mesajı (blok 6) varken breakpoint'i blok 6'ya koymak → *"No cache hit. You pay for a fresh cache write on every request and never get a read."*
- **Tez için sonuç:** "import satırları dosyanın başında olur" kuralının burada **performans-mühendisliği karşılığı** var: manifestte **kararlı/statik önek EN ÖNDE, göreve özel dinamik ek EN SONDA**. Sıra bozulursa cache hiç tutmaz — %90 maliyet + %85 gecikme avantajı tamamen kaybedilir.

**Bağlam-şişme / uzun-bağlam bozulması kanıt seti (üç bağımsız kaynak, yakınsak):**

| Kaynak | Kapsam | Sayı | Damga |
|---|---|---|---|
| **Chroma "Context Rot"** — trychroma.com/research/context-rot | 18 model (Claude Opus 4/Sonnet 4/3.5, GPT-4.1/4o/4-Turbo, Gemini 2.5 Pro/Flash/2.0 Flash, Qwen3) | *"LLMs do not maintain consistent performance across input lengths."* · **tek bir distraktör bile** temel performansı düşürüyor · düşük-benzerlikli needle-soru çiftlerinde bozulma hızlanıyor. LongMemEval odaklı-girdi (~300 token) ↔ tam-girdi (113K token) farkında Claude modelleri en büyük farkı gösteriyor | D (tez) / **X** (LongMemEval kesin yüzdesi — tam PDF'e inilmedi) |
| **Lost in the Middle** — arxiv.org/abs/2307.03172 | Uzun-bağlam konum etkisi | *"performance is often highest when relevant information occurs at the beginning or end... and significantly degrades when models must access relevant information in the middle."* U-eğrisi doğrulandı | D (tez) / **X** (sayısal fark — abstract'ta yok) |

İşçi promptu = tek uzmanlık + araç kısıtı + "sadece bunu yap" sınırı.** Bu desen Anthropic, Claude Code, LangGraph ve CrewAI'da aynı — çerçeveden bağımsız bir tasarım evrenseli görünümünde.

## SENTEZ — DÖRT AİLENİN KESİŞİMİNDE ÜÇ GERİLİM

**Gerilim 1 — "Fonksiyonlaştır" ↔ "fonksiyon büyüdükçe tutmuyor".** Görev-as-fonksiyon tezi tipli alan/sözleşme tarafında güçlü kanıtlı (AgentSpec %90+, DSPy Assertions %164, CrewAI guardrail retry). Ama Multi-IF (0,877→0,707 üç turda), FollowBench/ComplexBench mimarileri ve OpenAI'nin "karmaşık talimatı izleyemiyorsa böl" kriteri hep aynı şeyi söylüyor: **sözleşme ne kadar zenginse o kadar iyi DEĞİL — sözleşme ne kadar KÜÇÜK ve AYRIŞTIRILABİLİR ise o kadar iyi.** Doğru okuma: fonksiyon = küçük + tipli + tek sorumluluk; büyük iş = fonksiyon ZİNCİRİ, dev fonksiyon değil.

**Gerilim 2 — "Bağlamı daralt" ↔ "daraltılmış bağlam örtük kararları öldürür".** Anthropic (izolasyon = sıkıştırma + path-dependency azaltma) ↔ Cognition (izolasyon = çatışan örtük kararlar). Çözüm görev-sınıfı ayrımında: **bağımsız bilgi-toplama paralelleşir; birbirine bağımlı üretim/tasarım paralelleşmez.** Jarvis'in mevcut atlas koşumları (araştırma) güvenli tarafta; ileride "ship" işlerinde paralel işçi kullanılırsa bu fren gerekir.

**Gerilim 3 — "Koda dondur" ↔ "kod formatı tek başına sihirli değil".** Koda-dondurmanın kazançları gerçek (Voyager 15,3×, CodeAct %20, PAL +15pp, MCP kod-yürütme %98,7 token). Ama AWM Tablo 7 gösteriyor ki **kod-stili gösterim ile metin-stili gösterim arasındaki fark küçük** — kazanç FORMATTAN değil, **soyutlanmış/genellenmiş alt-rutin olmaktan** geliyor. Bu, kanondaki format-tax + capacity-not-format bulgularıyla aynı yöne bakıyor: **merdivenin değeri "kod" olmasında değil, "adlandırılmış, yeniden-kullanılabilir, sınırları belli birim" olmasında.**

### → HAFIZA-MANİFESTİ

**5. Üç-kademeli açılım: metadata (her zaman) → gövde (model kararı) → ek dosyalar (gerektiğinde).**

**6. Eager ↔ lazy ayrımı — ve Salih'in analojisine düzeltme.**
*"Imported files are expanded and loaded into context **at launch**"*, *"Splitting into imports helps organization but **doesn't reduce context**"*; max **4 hop**. → **Oturma:** **"import" analojisi biçim olarak doğru, maliyet olarak yanıltıcı.** Jarvis kanonundaki her bağlam dosyası iki sınıftan birine etiketlenir: **EAGER** (her oturumda yüklenmesi zorunlu — CLAUDE.md, kapsül, pano) ↔ **LAZY** (yalnız glob/konu tetiklenince okunur — wiki sayfaları, raporlar, kuyruk dosyaları). Bugünkü okuma-sırası fiilen eager; manifest bunu **açık** hale getirir ve lazy tarafı büyütür (m.22 katmanlı yerleşimin operasyonel hali).

**7. Manifest sırası kuralı: statik önek EN ÖNDE, dinamik ek EN SONDA.**
*"Place `cache_control` on the last block whose prefix is identical across the requests"*; aksi halde *"No cache hit. You pay for a fresh cache write on every request and never get a read."* Cache-read **0,1× fiyat**; min **1.024 token** (Sonnet ailesi); max **4 breakpoint**, lookback **20 blok**; TTL **5 dk** varsayılan / **1 sa** opsiyonel (yazma 2×) — platform.claude.com/docs/en/build-with-claude/prompt-caching **[D]**. Duyuruda: **%90 maliyet / %85 gecikme** kazancı — claude.com/blog/prompt-caching **[D]**.
→ **Oturma:** "import'lar dosyanın başında olur" kuralının **sert performans gerekçesi**. Görev-emri ve ajan-promptu şablonlarında blok sırası **sabitlenir**: [kanon/kimlik bloğu → rol bloğu → araç bloğu] hepsi statik; [göreve özel veri → tarih/SHA → tetikleyen mesaj] hepsi sonda. m.46(a)'nın SHA alanı **dinamik** olduğu için şablonun SONUNA taşınmalı — aksi halde her koşum cache'i kırar.

### → LOJİK→KOD MERDİVENİ

**9. Basamak kriteri SAYI değil DOĞA: "deterministik mi?" testi — ve N=3'ün gerçek statüsü.**
*"sorting a list via token generation is far more expensive than simply running a sorting algorithm"* · *"code is deterministic, this workflow is consistent and repeatable"* — Agent Skills **[D]**. *"...daha karmaşık sistemlere yalnızca basit çözümler başarısız olduğunda geçin"* + *"adım sayısını tahmin etmek zor/imkansızsa ve sabit yol kodlanamıyorsa"* — anthropic.com/engineering/building-effective-agents **[D]**. Google ADK üçlü kademe (template → graph/dinamik → LLM-yönlendirmeli) **[K]**. **"N tekrar → koda dondur" biçiminde ölçülmüş bir eşik BULUNAMADI [X]**; en yakın: Rule of Three (Roberts/Fowler 1999) — *"when similar code is used three times, it should be extracted"* **[K]**, LLM alanına transfer edilmiş literatürü yok.
→ **Oturma:** merdivenin basamak-geçiş kapısı **üç kontrol sorusu** olur: (i) adım sayısı önceden tahmin edilebilir mi? (ii) sabit yol kodlanabilir mi? (iii) model-kararına gerçekten ihtiyaç var mı? Üçüne de "evet/evet/hayır" → bir basamak yukarı (koda dondur). **Ayrıca m.43 için dürüstlük şerhi:** N=3 eşiği ampirik değil **ödünç konvansiyondur**; kanondaki "deneysel m.29" damgası bu bulguyla tutarlı — ama gerekçe satırına Rule of Three atfı ve "LLM alanında doğrulanmadı" notu düşülmeli.

→ **Oturma:** merdivenin işletim kuralı: **damıtma önce UCUZ ve DETERMİNİSTİK yapılır** (tekrar-tespiti = dedup + geçersiz-adım filtresi, LLM'siz); LLM'li damıtma ancak ucuz geçiş yetmezse. Ve **kazanç "kod" olmasından değil "adlandırılmış, sınırları belli, yeniden-kullanılabilir birim" olmasından geliyor** — bu, kanondaki format-tax + capacity-not-format bulgularıyla aynı yöne bakar ve merdivenin ORTA basamağını (kontrollü-NL/DSL) meşrulaştırır: her şeyi koda çevirmek gerekmiyor.

*(Merdivenin dördüncü basamağı için uyarı: DSPy "compile" kazançları gerçek — GPT-3.5 **>%25**, Llama2-13b **%65**, MIPROv2 **%13'e varan**; derleme "dakikalar/onlarca dakika", ~150-300 doğrulama örneği — arxiv.org/abs/2310.03714 + 2406.11695 **[D]**. **Ama makalelerde açık "Limitations" bölümü YOK; "ne zaman işe yaramaz" sorusu araştırılmamış [D-negatif].** Otomatik derleme jarvis'e girerse üretim-öncesi elle doğrulama katmanı zorunlu — m.6 kör-onay-yok ile uyumlu.)*

**11. Delegasyon-sözleşmesi dörtlüsü + arıza eşlemesi — ve delegasyonun varsayılan KAPALI olması.**
*"Each subagent needs an **objective**, an **output format**, **guidance on the tools and sources** to use, and clear **task boundaries**"*; belgelenmiş arıza: *"one subagent explored the 2021 automotive chip crisis while **2 others duplicated work**"* — anthropic.com/engineering/multi-agent-research-system **[D]**. → **Oturma:** lider/işçi bölümünün **zorunlu 4 alanı** budur; jarvis'in görev-emri şablonu üçünü zaten taşıyor, **`task boundaries` (kapsam sınırı / "sana ait OLMAYAN") alanı en zayıf halka** — ve tam da bu eksiklik iş-tekrarı/boşluk arızasını üretiyor (belgeli). Ayrıca: CrewAI'nin varsayılan-kapalı delegasyonu m.42(d) katı-başlangıç ilkesiyle birebir aynı yön → **kanon burada sektörle hizalı, kanıt eklenebilir.** OpenAI'nin tool-risk derecelendirmesi m.42(e) RİSK boyutuna hazır bir kademe verir; `handoff ↔ as_tool` ayrımı m.30'un otomasyon↔canlı-ajan merdiveniyle (tetik devri ↔ prompt devri) yapısal olarak aynı ayrımdır.

**12. Lider-promptu ≠ işçi-promptu kalıbı + paralellik-uygunluk testi.**
Lider: *"You are a team supervisor managing a research expert and a math expert. For current events, use research_agent..."* ↔ İşçi: *"You are a math expert. Always use one tool at a time."* — langgraph-supervisor-py README **[D, dolaylı]**. `description` = **çağrı-koşulu**: *"Claude uses each subagent's description to decide **when to delegate**"*; alt-ajan *"returns only the summary"* — code.claude.com/docs/en/sub-agents **[D]**. Paralellik sınırı: *"Actions carry implicit decisions, and conflicting decisions carry bad results"*, Flappy Bird örneği — cognition.com/blog/dont-build-multi-agents **[D]**. Kademeleme rejim ayrımı: FrugalGPT **%98'e kadar maliyet düşüşü** (2305.05176 **[D]**) ↔ Anthropic **~15× token, %90,2 kalite** — aynı mekanizma, ters hedef.
