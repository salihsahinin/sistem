## §2 — METRİK-SEÇİMİ HÜKMÜ

### M1 — "Bellek kullanımı %X" tek başına İZLENMEZ (HÜKÜM)

Görev Yöneticisi'nin gösterdiği % = (Toplam − Available)/Toplam. Available = **Free + Zeroed + Standby** `[D-belge: MS PerfGuide, Clint Huffman, MS PFE — "The Available MBytes counter is the sum of all free, zero ... and standby pages of physical memory"]`. Windows standby listesini bilinçli doldurur: *"low 'free' memory is fine, but it is not fine to be low on 'available' memory"* `[D-belge, aynı kaynak]`.

**Ama bu makinede tasarım-gereği-doluluk savunması ZAYIFTIR:** Available'ın %93,7'si standby, gerçekten boş liste ortalama 128 MB, minimum 11 MB `[D-ölçüm]`. Yani "%86 dolu" göstergesi burada iyimser değil, **kötümser tarafta doğru**: sistem her yeni tahsisi cache koparak karşılıyor.

**Lojik form (m.38):**
`fiziksel-%(t) yüksek ∧ FreeZero(t) ≫ 0 → BENİGN (tasarım gereği)`
`fiziksel-%(t) yüksek ∧ FreeZero(t) → 0 ∧ PageReads(t) > 0 → GERÇEK BASKI` ← **bu host'un durumu**

### M2b — ALT-HÜKÜM: `% Committed Bytes In Use` YANILTICIDIR, payda RAM olmalıdır

`% Committed = Commit / CommitLimit` ve `CommitLimit = RAM + pagefile`. Sistem-yönetimli pagefile, commit charge limitin %90'ına ulaştığında **otomatik büyür** `[D-belge: MS Learn, page file introduction, ms.date 2026-02-12]`. Sonuç: **payda baskı arttıkça genişler, oran kendini "iyi" gösterir.** Bu host'ta %79 sakin görünüyor; aynı anda ham oran **1,48×** kritik.

**HÜKÜM:** JARVIS izlemesinde birincil taahhüt metriği **`Commit / FizikselRAM`**'dir; `% Committed Bytes In Use` yalnız ikincil (pagefile tükenmesi alarmı olarak) tutulur.

*Bu, kaynakta hazır bulunmayan bir metrik seçimidir — `[Ö-türetilmiş]`, m.39 gereği Carvis kontrolünden geçti, m.29 deneysel damgalı.*

### M3 — Memory Compression store = basınç İMZASI (kanıt değil, gösterge)

Sıkıştırma yalnız MM baskı algıladığında tetiklenir: *"When MM feels memory pressure, it will compress unused pages instead of writing them to disk"* `[D-belge: MS Windows Insider Hub, Ethan Creeger (PM, Base Platform), ~2015 arşiv — **NİTELEYİCİ TAŞINDI: 2015 tarihli arşiv gönderi; güncel build davranışı doğrudan doğrulanmadı**]`. Bu host'ta store **943 MB** `[D-ölçüm]` → sistem yalnızca cache biriktirmiyor, **sıkıştırma yapmaya karar vermiş durumda**.

### M4 — Süreç-başına atıf Working Set ile YAPILMAZ

WS paylaşılan sayfaları (DLL, mapped file) her süreçte ayrı sayar `[D-belge: MS PerfGuide WS tanımı]`. Private Bytes = *"total amount of memory allocated for the specific process, not including memory shared with other processes"* `[D-belge: MS Learn, Windows Drivers, ms.date 2025-07-10]`.
**Yerel kanıt:** ΣWS = 17.061 MB > fiziksel 16.128 MB `[D-ölçüm]`.
**HÜKÜM:** "bu uygulama ne kadar RAM yiyor" sorusuna **Private Bytes** ile cevap verilir; WS yalnız "şu an fiziksel olarak yerleşik" sorusuna cevaptır. §1.5 tablosu her iki sütunu bu yüzden taşır.

### 9.3 Desen gözlemleri (g23 için — ASIL ÇIKTI)

**D1 — Öz-beyan boşluk bölümü, ucuz denetçi ikamesidir (2/2 tuttu).**
Her iki alt-ajan da *ayrı denetçi ajan koşulmadan* kendi kusurunu beyan etti: B "7/6 arama kullandım, 1 fazla" + "kaldıraç-4'ü koşamadım"; A "10 kalemlik UNCERTAIN listesi". Bu, ingest turundaki **sınır-denetçisi ilkesinin** (F2 denetçisi bir lensin "n=23" icadını yakalamıştı) ucuz varyantıdır: prompt'a **zorunlu boşluk-beyanı bölümü** koymak, ikinci ajan maliyeti ödemeden ilk süzgeci kurdu.
**AMA İKAME DEĞİL, İLK SÜZGEÇ:** A'nın UNCERTAIN #3 kalemini (ΣWS aşırı-sayım) üretici seviyesinde **yerel ölçümle** ben kapattım (§1.5). Yani öz-beyan **boşluğu işaretler, kapatmaz** — kapatma hâlâ üretici işidir. → g23 desen adayı: *öz-beyan = ucuz süzgeç ∧ ¬(öz-beyan = denetçi)*.

**D2 — Ölçüm şeridi ∥ araştırma şeridi ayrımı temiz bölündü.**
İki şerit hiç kesişmedi: ölçüm salt yerel/deterministik, araştırma salt dış/olasılıksal. Devir arayüzü tek yönlü (araştırma → derleyici). Bu, "dar-ajan pipeline ilkesinin" (g20/H48-H51) **kronolojik değil KİPSEL partisyon** varyantıdır: bölme ekseni zaman değil **bilgi kaynağı türü**. → g23'e yeni partisyon ekseni adayı.

**D3 — Kota bölüştürme kusuru: rezerv payı bırakılmadı.**
15'lik kota alt-ajanlara 8+6=14 olarak bölündü, 1 rezerv üreticide tutuldu. B kotasını 1 aştı → toplam tam 15 oldu, **marj sıfır kaldı**. Üretici hiç arama yapamadı. Eğer B 2 aşsaydı emir ihlal edilecekti. → **kural adayı: kota bölüşümünde ≥%15 rezerv üreticide tutulur** (bu koşumda %6,7 tutuldu, yetersiz).

**D4 — Ölçüm-önce sırası tez/antitez'den daha verimli çıktı.**
Alt-ajan A'nın kaynaklayamadığı 3 kalemden 2'si yerel ölçümle kapandı (ΣWS aşırı-sayım kanıtı; bant yokluğunun bu host'a etkisi). Yani **dış-tarama boşluğunu iç-ölçüm kapatıyor** — m.35 ölçüm-öncelikli ilkesinin bu vakada ampirik desteği. m.40b tam kontrat (tez/antitez/hakem) koşulsaydı aynı 2 kalem kapanmayacaktı, çünkü ikisi de **yerel-gerçeklik** kalemiydi, literatür kalemi değil.
→ g23 desen adayı: *soru-sınıfı(g) = yerel-gerçeklik → ölçüm-şeridi ≻ diyalektik-şerit* (kaynak tarama ikincil kalır).

**D5 — WMI güvenilmezliği tek çağrıda yakalandı ve raporu kurtardı.**
İlk ölçüm `commit %100` verdi (`FreeVirtualMemorySize=0`). Çapraz-doğrulama (perf sayacı) yapılmasaydı raporun tamamı yanlış bir kriz teşhisi üzerine kurulacaktı. → **kural adayı: her kritik ham metrik ≥2 bağımsız API'den okunur** (m.37 triangülasyonunun ölçüm katmanındaki karşılığı).

**D6 — GİZLİ 4. MODEL KATMANI: web araması kendi model maliyetini taşıyor (ölçüm-bankı boşluğu).**
Koşum kapandıktan sonra gelen gerçek panel ölçümü, beyan edilen 3-ajanlı topolojinin **eksik** olduğunu gösterdi: 15 web araması **Haiku 4.5** üzerinde **181,6K girdi / 7,9K çıktı = $0,3712** tükettti. Bu katman ne alt-ajanların token raporlarında (114.911) ne de üreticinin çağrı sayımında görünüyordu — **§9.2/§10'un ilk sürümü bu maliyeti tamamen kaçırdı.**
→ **ölçüm-bankı kalemi:** "web araması ≤N" freni bir **arama sayısı** kotasıdır ama arkasında **ölçülmeyen bir token kotası** vardır; bu koşumda arama başına ≈12,1K girdi tokeni / ≈$0,025. → **kural adayı:** koşum-imzası şablonuna `arama-katmanı maliyeti` satırı eklenir; aksi halde her araştırma koşumu maliyetini sistematik olarak **eksik** raporlar.

**D7 — Kestirim kapısı TUTTU ama yüksek yönde kalibresiz (Öneri B'ye doğrudan veri).**
